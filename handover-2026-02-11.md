6. **Politically neutral** — no rankings, no recommendations, no partisan framing.

## 6. Key Features in Detail

### Belofte-kloof (Promise Gap)
On motion detail pages (`/moties/[id]`), shows the gap between how a party was predicted to vote (based on election promises) vs. how they actually voted. Uses dual vote bars — predicted (striped/dashed) vs. actual (solid). Includes reliability indicator and confidence badge.

### Mandate Consistency Score (MCS)
Per-party scoring on `/partijen/[id]`. Calculates: `MCS = consistent votes / (consistent + inconsistent votes) × 100%`. Broken down by theme (Defensie, Migratie, Klimaat, etc.). Current range: SP at 97% to VVD at 37%.

### Consensus Matrix
On `/verbinding`. Pre-computed server-side via `GET /votes/consensus`. 15×15 heatmap showing which parties agree most/least. Uses ALL 12,444 votes. PartyBadge pills in pair rows. Minimum 10 common votes required for a pair to be shown.

### Transparency Layer
Methodology panel accessible from:
- "Begrippen" button in desktop nav
- "Methodologie & begrippen" links on detail pages (moties, beloften, partijen)
- Footer "Methodologie" link
Contains searchable glossary with Dutch definitions for all CivicStat scores, match types, specificity levels, and data sources.

## 7. Database Schema (22 models)

```
Party ──┬── Mp ──── VoteRecord
        ├── Vote ── Motion ──┬── MotionSponsor
        ├── Program          ├── PromiseMotionMatch ── Promise
        │   └── ProgramPassage   └── MotionProgramMatch
        │       └── MotionProgramMatch
        └── Promise ──┬── PromiseMotionMatch
                      └── VotePrediction ── PartyPrediction

Standalone: User, AuditLog, AlgorithmVersion, RawIngest, SyncState
Consultation ── ConsultationQuestion ── ConsultationResponse
Position
```

Key relationships:
- `Vote` → `Motion` (via motionId, ~85% linked)
- `VoteRecord` → `Vote` + `Mp` (individual roll-call records)
- `MotionSponsor` → `Motion` + `Mp` (indiener/medeindiener)
- `Promise` → `Program` → `Party` (election promise chain)
- `PromiseMotionMatch` → `Promise` + `Motion` (keyword matches with confidence)

## 8. ETL Pipeline

### CLI Commands
```bash
cd packages/etl

# Full incremental sync (what the cron runs)
npx tsx src/index.ts sync

# Individual ingest commands
npx tsx src/index.ts moties          # Motions since TK2023
npx tsx src/index.ts stemmingen      # Votes + motion linking
npx tsx src/index.ts sponsors        # ZaakActor → MotionSponsor
npx tsx src/index.ts fracties        # Parties
npx tsx src/index.ts kamerleden      # MPs
npx tsx src/index.ts programmas      # Election program passages

# Promise pipeline
npx tsx src/index.ts seed-promises   # Seed all 15 party promise sets
npx tsx src/index.ts match-promises <party> <year>  # Keyword matching
```

### GitHub Actions Cron
File: `.github/workflows/etl-sync.yml`
- Schedule: every hour at :15 (`cron: '15 * * * *'`)
- Also supports manual trigger (`workflow_dispatch`)
- Runs `sync` command which calls moties + stemmingen + sponsors
- Requires `DATABASE_URL` secret in GitHub repo settings

### Data Source
Tweede Kamer OData API v4: `https://gegevensmagazijn.tweedekamer.nl/OData/v4/2.0/`
- `Zaak` → motions (filtered by `Soort eq 'Motie'`)
- `Besluit` → vote decisions (contains `Stemming` array in raw data)
- `ZaakActor` → motion sponsors
- `Persoon` / `FractieZetelPersoon` → MPs with party assignments
